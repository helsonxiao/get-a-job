# 四维度评估规则（v3 - 纯规则打分 + AI介入标记）

## 解析说明
- 本文件**只包含固定规则**，不涉及任何 AI 推断。
- 所有打分逻辑均基于 `profile_filled.md` 和 `jd_fields.md（v2）` 中的结构化字段，脚本可逐条翻译为 `if/else`。
- **输出格式**：固定 JSON，包含各维度得分、综合得分、硬性过滤结果，以及一个 **`ai_intervention_needed`** 标记。

---

## 优先级说明
1. **第一步（硬性过滤）**：先执行下方「硬性淘汰规则」，若命中任意一条，直接返回总分 0 分并标记 `"status": "REJECTED"`，不再进行后续打分。
2. **第二步（维度评分）**：通过硬性过滤后，按四个维度分别计算得分（每个维度满分 10 分）。
3. **第三步（综合加权）**：综合得分 = 财务回报得分×40% + 职业发展得分×30% + 资源匹配度得分×20% + WLB得分×10%。
4. **第四步（生成 AI 介入标记）**：根据下方「AI 介入触发条件」，输出 `ai_intervention_needed: true/false`。

---

## 一、硬性淘汰规则（一票否决，命中即淘汰）

| 规则编号 | 判断条件（脚本逻辑） | 淘汰结果 |
| :--- | :--- | :--- |
| H-01 | `JD.公司所在城市` **不在** `Profile.可接受城市` 列表中 | 淘汰（城市不可接受） |
| H-02 | `JD.公司所属行业` **包含于** `Profile.拒绝行业` 列表中 | 淘汰（行业被拒绝） |
| H-03 | `JD.公司规模` **等于** `Profile.拒绝公司规模`（如 <20人） | 淘汰（规模太小） |
| H-04 | `JD.职位薪资下限` **＜** `Profile.硬性最低可接受年薪（30万）` | 淘汰（薪资不达标） |
| H-05 | `JD.出差频率要求` **等于** “长期驻场” 且 `Profile.接受出差` 为“否” | 淘汰（出差强度超标） |
| H-06 | `JD.实际加班强度` **等于** “996” 或 “大小周” | 淘汰（加班强度超标） |
| H-07 | `JD.排除关键词` 匹配 `Profile.排除关键词` 黑名单（如 995/无休） | 淘汰（关键词命中） |

---

## 二、各维度评分细则（满分均为 10 分）

### 维度 1：财务回报（权重 40%）

| 评分项 | 分值规则（脚本计算） | 上限 |
| :--- | :--- | :--- |
| **薪资下限达标** | 若 `JD.职位薪资下限` >= `Profile.期望最低年薪（35万）`，得 **4分**；否则得 0 分 | 4分 |
| **薪资中位数达标** | 若 `(JD.下限 + JD.上限)/2` >= `Profile.期望中位数（42.5万）`，得 **4分**；否则得 0 分 | 4分 |
| **薪资上限惊喜** | 若 `JD.职位薪资上限` >= `Profile.期望上限×1.2（60万）`，得 **1分** | 1分 |
| **股票/期权激励** | 若 `JD.是否有股票/期权` == “是”，得 **0.5分** | 0.5分 |
| **福利价值** | 遍历 `JD.福利标签`，若包含“补充公积金/补充医疗/企业年金/房补”中的任意一项，**每项 +0.25分**（最多加至 **0.5分**） | 0.5分 |

> **该维度总分 = 上述得分之和，封顶 10 分。**

---

### 维度 2：职业发展（权重 30%）

| 评分项 | 分值规则（脚本计算） | 上限 |
| :--- | :--- | :--- |
| **技术栈重合度** | 计算 `JD.技术栈标签` 与 `Profile.技术栈` 的交集数量。<br>重合 1 个得 0.5分，重合 2 个得 1分，重合 3 个得 2分，重合 ≥4 个得 **3分** | 3分 |
| **公司阶段价值** | 若 `JD.公司融资阶段` 在 [“B轮”,”C轮”] 中，得 **2分**；<br>若在 [“D轮及以上”,”已上市”] 中，得 **1分**；<br>若 `JD.公司性质` == “国企” 得 **1分**（可叠加，但封顶2分） | 2分 |
| **业务方向匹配** | 计算 `JD.公司所属行业` 与 `Profile.行业经验标签` 的**直接字符串交集**：<br>有任意重合则得 **2分**，否则得 0 分 | 2分 |
| **团队规模契合** | 若 `JD.部门/团队规模` 落在 `Profile.偏好团队规模（10~50人）` 区间内，得 **1分**；否则得 0 分 | 1分 |
| **经验学历兼容** | 若 `JD.经验要求` 包含“5-10年”或“不限”，且 `JD.学历要求` 包含“本科”或“不限”，得 **1分** | 1分 |
| **技术深度信号** | 若 `JD.任职要求描述` 中包含“架构设计/性能优化/技术选型”中的任意关键词，得 **1分** | 1分 |

> **该维度总分 = 上述得分之和，封顶 10 分。**

---

### 维度 3：资源匹配度（权重 20%）

| 评分项 | 分值规则（脚本计算） | 上限 |
| :--- | :--- | :--- |
| **城市完美匹配** | 若 `JD.公司所在城市` == `Profile.当前城市（无锡）`，得 **5分** | 5分 |
| **城市次优匹配** | 若上一条不成立，但 `JD.公司所在城市` **在** `Profile.可接受城市（上海/杭州）` 中，得 **2分** | 2分（替代上一条，不叠加） |
| **行业经验重叠** | 若 `JD.公司所属行业` 与 `Profile.行业经验标签` 有任意一项重合（如“教育”），得 **2分** | 2分 |
| **公司规模偏好** | 若 `JD.公司规模` 在 [“500-2000人”,”2000人以上”] 中，或 `JD.公司融资阶段` 为“已上市”，得 **1分** | 1分 |
| **特殊资源** | 默认 0 分（预留手动注入接口，外部可注入 +2 分） | 2分（手动） |

> **该维度总分 = 上述得分之和，封顶 10 分。**

---

### 维度 4：工作生活平衡（WLB）（权重 10%）

| 评分项 | 分值规则（脚本计算） | 上限 |
| :--- | :--- | :--- |
| **工作模式弹性** | 若 `JD.工作模式` == “远程办公”，得 **3分**；<br>若 == “混合办公”，得 **2分**；<br>若 == “现场办公”，得 0 分 | 3分 |
| **弹性福利信号** | 若 `JD.福利标签` 包含“弹性工作”或“不打卡”，得 **2分** | 2分 |
| **企业规范性** | 若 `JD.公司规模` **≥** “2000人以上” 或 `JD.公司融资阶段` == “已上市”，得 **1分** | 1分 |
| **加班强度评估** | 若 `JD.实际加班强度` == “965/双休”，得 **3分**；<br>若 == “弹性不打卡” 或 “未知”，得 **1分**；<br>若 == “大小周”或“996”，得 0 分（且 H-06 会直接淘汰） | 3分 |
| **通勤便利** | 若 `JD.公司所在城市` == `Profile.当前城市（无锡）`，得 **1分** | 1分 |

> **该维度总分 = 上述得分之和，封顶 10 分。**

---

## 三、AI 介入触发条件

| 触发编号 | 触发条件 | 触发说明 |
| :--- | :--- | :--- |
| A-01 | **WLB 维度得分 ≤ 3** | 规则得分过低，但可能是因 JD 信息不全导致（如未填写“弹性工作”标签），需要 AI 联网查公司真实口碑确认 |
| A-02 | **WLB 维度得分 ≥ 7** | 规则得分偏高，需要 AI 交叉验证（如公司是否真的 965，有无隐藏加班文化） |
| A-03 | **职业发展维度中“业务方向匹配”得分为 0**，但 JD 所属行业与 Profile 经验明显有语义关联（如 JD 写“知识付费”，Profile 有“在线教育”） | 规则无法识别语义相似，需 AI 做文本相似度修正 |
| A-04 | **综合得分在 6.0 ~ 7.5 之间**（百分制 60~75 分） | 处于“可去可不去”的模糊区间，需要 AI 综合判断给出最终建议 |
| A-05 | **JD 中“岗位职责描述”或“团队介绍”字段为空**，无法提取“技术深度信号” | 需 AI 联网搜索该公司该职位补充信息 |
| A-06 | **硬性过滤结果为 PASS，但用户要求深度分析**（用户主动触发） | 用户想深入了解某个机会 |

> **规则**：若 A-01 至 A-06 中任意一条为 `true`，则 `ai_intervention_needed = true`，否则为 `false`。

  }
}
