# 四维度评估规则（v4.0 - 纯规则打分 + AI介入标记）

## 解析说明
- 本文件**只包含固定规则**，不涉及任何 AI 推断。
- 所有打分逻辑均基于 `profile.md` 和 `jd_fields.md（v2）` 中的结构化字段，脚本可逐条翻译为 `if/else`。
- **输出格式**：固定 JSON，包含各维度得分、综合得分、硬性过滤结果，以及一个 **`ai_intervention_needed`** 标记。
- **方法论依据**：冰山模型 (McClelland 1973) / 人岗匹配三层模型 / 选Offer第一性原理 / 总包折现率 / 真实时薪公式 (D2D) / 通勤幸福临界点研究。

---

## 优先级说明
1. **第一步（硬性过滤）**：执行「硬性淘汰规则」，若命中任意一条且置信度 ≥ `reject_confidence_floor` (默认 0.6)，直接返回总分 0 分并标记 `"status": "REJECTED"`；置信度不足则标记 REVIEW 不出局。
2. **第二步（维度评分）**：通过硬性过滤后，按四个维度分别计算得分（每个维度满分 10 分，超出封顶）。
3. **第三步（综合加权）**：综合得分 = 财务×`weight_finance%` + 成长×`weight_growth%` + 资源×`weight_resource%` + WLB×`weight_wlb%`（权重取自画像，默认 30/30/10/30，和不必为 100，引擎内部归一化）。
4. **第四步（生成 AI 介入标记）**：根据「AI 介入触发条件」，输出 `ai_intervention_needed: true/false`。

---

## 一、硬性淘汰规则（命中且置信度 ≥ 0.6 即淘汰）

| 编号 | 名称 | 判断条件 | 阈值来源 | 置信度规则 |
| :--- | :--- | :--- | :--- | :--- |
| H-01 | 城市不可接受 | `job.city` 不在 `profile.all_acceptable_cities()` 中 | 画像: 可接受城市 + 当前城市 | 迁移假定城市 conf=0.4 (REVIEW), 抓取所得 conf=1.0 |
| H-02 | 行业被拒绝 | `company.industry` 命中 `profile.reject_industries` | 画像: 拒绝行业列表 | 命中即 conf=1.0 |
| H-03 | 公司规模过小 | `company.scale_max` < `profile.reject_scale_below` (默认 20 人) | 画像: 拒绝规模下限 | 命中即 conf=1.0 |
| H-04 | 薪资低于硬性下限 | `job.salary.min_10k` < `profile.hard_min_salary_10k` (默认 30 万) | 画像: 硬性最低年薪 | 面议/未知 conf=0.0, 命中 conf=1.0 |
| H-05 | 出差强度超标 | JD 信号 `travel==long_term` 且 `profile.accept_travel=False` | 画像: 是否接受出差 + JD 信号 | 置信度来自信号推断 |
| H-06 | 加班强度超标 | JD 信号 `overtime==heavy` (996/大小周/单休) | 画像隐式 + JD 信号 | 置信度来自信号推断 |
| H-07 | 命中排除关键词 | JD 文本命中 `profile.blacklist_keywords` | 画像: 黑名单关键词 | 命中即 conf=1.0 |
| H-08 | 外包/驻场岗位 | JD 信号 `outsourcing==True` 且 `profile.accept_outsourcing=False` | 画像: 是否接受外包 + JD 信号 | 置信度来自信号推断 |
| H-09 | 学历硬性不符 | 岗位 `edu.rank` < 本人 `profile.education_rank()` (rank 越小要求越高: 1=博士 2=硕士 3=本科 4=大专) | 画像: 最高学历 | 画像未填 conf=0.4 (REVIEW); 命中 conf=1.0 |
| H-10 | 经验年限硬性不符 | 岗位 `exp.min_years` > 本人 `total_years + 1` → fatal; 1 年以内差距 → REVIEW | 画像: 工作总年限 | 画像未填 conf=0.4; 超出 1 年以上 conf=1.0; 1 年内 conf=0.5 |

**置信度机制**:
- `confidence ≥ 0.6` (默认 `reject_confidence_floor`) → `fatal` (直接淘汰)
- `confidence < 0.6` → `suspicion` (不出局, 标记 AI 复核)
- 阈值可在 `scoring_config.json` 的 `reject_confidence_floor` 中覆盖

## 二、各维度评分细则（满分均为 10 分，超出封顶）

### 维度 1：财务回报 finance（默认权重 30%）

| 编号 | 评分项 | 默认上限 | 分值规则 | 方法论 |
| :--- | :--- | :--- | :--- | :--- |
| F-01 | 薪资下限达标 | 4.0 | `min_10k >= profile.expect_min_salary_10k` (默认 35 万) → 满分; 否则 0 | 三层模型·愿留下 |
| F-02 | 薪资中位数达标 | 3.5 | `(min+max)/2 >= profile.expect_mid_salary_10k` (默认 42.5 万) → 满分; 否则 0 | 三层模型·愿留下 |
| F-03 | 薪资上限惊喜 | 1.0 | `max_10k >= profile.salary_surprise_threshold_10k` (期望上限×1.2, 默认 60 万) → 满分 | 三层模型·愿留下 |
| F-04 | 股票/期权激励 | 0.5 | **折现率分级**: 上市+RSU→满分; 未上市+RSU→70%; 未上市+期权→30%; 无股权→0 | **总包折现率** |
| F-05 | 高价值福利 | 0.5 | 福利含"补充公积金/补充医疗/企业年金/房补", 每项 +0.25 封顶 0.5 | 总包折现·现金等价物 |
| F-06 | 薪资构成质量 | 0.5 | 明确月薪×月数 (如 25K×14薪) → 满分; 仅年薪范围 → 60%; 面议 → 0 | **总包折现·确定性** |

> 维度满分: 10.0

---

### 维度 2：职业发展 growth（默认权重 30%）

| 编号 | 评分项 | 默认上限 | 分值规则 | 方法论 |
| :--- | :--- | :--- | :--- | :--- |
| G-01 | 技术栈重合度 | 3.0 | JD 技术标签与画像技能交集: 1 个 0.5, 2 个 1, 3 个 2, ≥4 个 3 | 冰山模型·显性层 |
| G-02 | 公司阶段价值 | 2.0 | B/C 轮 → 满分; D 轮+/已上市 → 1; 国企 → 1 (可叠加封顶 2) | **第一性原理·成长性** |
| G-03 | 业务方向匹配 | 2.0 | `company.industry` 与画像 `industry_tags` 字面交集 (语义匹配走 A-03) | 冰山模型·动机 |
| G-04 | 团队规模契合 | 1.0 | JD 团队规模落在 `profile.team_size_min~max` 区间 → 满分 | 三层模型·胜任 |
| G-05 | 经验学历兼容 | 0.5 | 经验含"5-10年/不限" 且 学历含"本科/不限" → 满分 | 冰山模型·显性层 |
| G-06 | 技术深度信号 | 1.0 | JD 含"架构设计/性能优化/技术选型" 任一 → 满分 | 三层模型·胜任 |
| G-07 | 技术前瞻性 | 0.5 | JD 涉及 AI/云原生/Web3/低代码/跨端/大数据 等热点 → 满分 | **第一性原理·3 年价值** |

> 维度满分: 10.0

### 维度 3：资源匹配 resource（默认权重 10%）

> 语义扩展为"平台与文化适配", 代码 key 仍为 `resource`

| 编号 | 评分项 | 默认上限 | 分值规则 | 方法论 |
| :--- | :--- | :--- | :--- | :--- |
| R-01 | 城市完美匹配 | 4.0 | `job.city == profile.current_city` → 满分; 在可接受城市 → 2.0 (替代) | 三层模型·愿留下 |
| R-02 | 行业经验重叠 | 2.0 | `company.industry` 与画像 `industry_tags` 有任意重合 → 满分 | 三层模型·胜任 |
| R-03 | 公司体量偏好 | 1.0 | 规模 500-2000 或 2000+ 或 已上市 → 满分 | 总包折现·稳定性 |
| R-04 | 特殊资源 (手动) | 1.0 | 默认 0, 预留手动注入接口 | 用户自定义加分 |
| R-05 | 文化适配信号 | 2.0 | JD 推断文化标签命中 `profile.tech_culture` → 满分; 推断为传统且偏好技术驱动 → 0 | **冰山模型·隐性层** |

> 维度满分: 10.0

---

### 维度 4：工作生活平衡 wlb（默认权重 30%）

| 编号 | 评分项 | 默认上限 | 分值规则 | 方法论 |
| :--- | :--- | :--- | :--- | :--- |
| W-01 | 工作模式弹性 | 3.0 | 远程 → 满分; 混合 → 2.0; 现场 → 0 | 真实时薪·D2D |
| W-02 | 弹性福利信号 | 2.0 | 福利含"弹性工作/不打卡" → 满分 | 真实时薪·D2D |
| W-03 | 企业规范性 | 1.0 | 规模 ≥2000 或 已上市 → 满分 | 总包折现·稳定性 |
| W-04 | 加班强度 | 3.0 | 965/双休 → 满分; 弹性不打卡/未知 → 1.0; 大小周/996 → 0 (且 H-06 淘汰) | **真实时薪·D2D** |
| W-05 | 通勤便利 | 1.0 | 同城 + GPS: Haversine 直线距离 → 估算通勤分钟对比 `max_commute_minutes`; ≤上限→满分, ≤1.5倍→半分, >1.5倍→0; 无 GPS 回退城市匹配; 未填 max_commute 用距离档位 (≤15km 满分, ≤30km 半分, >30km 零分) | **通勤临界点研究** |

> 实际合计 10.0

**W-05 通勤估算公式**:
```
直线距离 = Haversine(job.gps, profile.home_lng/lat)
估算通勤分钟 = 直线距离(km) ÷ 30km/h × 60 × 1.3 蜿蜒系数 + 10min 等车
```

## 三、AI 介入触发条件

| 编号 | 触发条件 | 触发说明 | 方法论 |
| :--- | :--- | :--- | :--- |
| A-01 | WLB 维度得分 ≤ 3 | 可能 JD 信息不全, 需 AI 联网查公司真实口碑 | 真实时薪·D2D |
| A-02 | WLB 维度得分 ≥ 7 | 高分需交叉验证 (如公司是否真 965) | 真实时薪·D2D |
| A-03 | G-03 业务方向匹配=0 但有语义关联 (如 JD 写"知识付费", Profile 有"在线教育") | 规则无法识别语义相似, 需 AI 文本相似度修正 | 冰山模型·动机 |
| A-04 | 综合得分 6.0~7.5 | 模糊区间, 需 AI 综合判断 | 通用 |
| A-05 | JD 岗位职责/团队介绍为空 | 无法提取技术深度信号, 需 AI 联网补充 | 三层模型·胜任 |
| A-06 | 用户主动触发深度分析 | 用户想深入了解 | 用户驱动 |
| A-07 | (保留位, 未启用) | - | - |
| A-08 | (保留位, 未启用) | - | - |
| A-09 | R-05 文化适配=0 且画像有文化偏好 且总分 ≥6.0 | 可能 JD 未体现而非真的不匹配, 需 AI 联网查公司氛围 | **冰山模型·隐性层** |
| A-10 | 公司未上市 + 规模<100 + JD 含"急招/大量招聘/极速扩张"信号 | 稳定性风险, 需 AI 联网查融资/裁员/经营异常 | **总包折现·稳定性** |

> **规则**：若 A-01 ~ A-10 中任意一条触发，则 `ai_intervention_needed = true`。

## 四、可配置项

### 4.1 评分项上限 (scoring_config.json)

所有评分项的 `max_points` 可在 `data/scoring_config.json` 中覆盖, 字段名形如 `f01_max` / `g07_max` / `r05_max` 等。未填则用代码默认值。

### 4.2 硬规则置信度下限

`reject_confidence_floor` (默认 0.6) 可在 `scoring_config.json` 中覆盖。

### 4.3 价值观权重预设 (profile.py `WEIGHT_PRESETS`)

画像编辑页提供 5 套一键预设方案:

| 预设名 | growth | finance | wlb | resource |
|--------|--------|---------|-----|----------|
| 平衡型(默认) | 30 | 30 | 30 | 10 |
| 成长优先(技术人) | 40 | 25 | 25 | 10 |
| 财务优先(赚钱) | 25 | 40 | 25 | 10 |
| 生活优先(WLB) | 25 | 25 | 40 | 10 |
| 资源优先(管理者) | 30 | 30 | 10 | 30 |

### 4.4 画像阈值字段

所有硬规则的阈值都在 `data/profile.md` 中编辑, 规则概览页只展示当前值和来源字段, 不直接编辑阈值。
