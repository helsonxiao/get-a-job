一、背景与目标

求职决策三个层次：岗位层（值不值得投）→ 公司层（值不值得去）→ 行业层（值不值得待）。当前已有岗位打分与公司图鉴，行业层是缺失一环——行业选择往往比具体岗位更影响长期收益。

本期目标：①行业总览（在招规模/薪资/风险一眼可见）②行业下钻（薪资结构/技能/信号/代表公司）③与岗位详情链路打通 ④零成本起步，尽量复用现有聚合数据。
非目标：行业趋势时间序列（数据积累不足）、行业政策分析（列入路线图）、后端数据模型改动。

三、方案对比

A · 最小 观察台内嵌 Tab
纯前端：观察台加第 5 个 Tab「行业观察」，总览表 + 行业详情抽屉（复用 obs-drill）。

后端：无
工期：0.5-1 天
优点：最快、零后端
缺点：详情空间受限，政策分析无处挂载
B · 推荐 独立行业观察视图
启用侧边导航占位项，独立视图：行业卡片墙 + 完整行业详情页。

后端：+1 只读聚合接口（约 60 行 SQLite 查询）
工期：2-3 天
优点：行业一等公民、空间充足、政策分析有挂载位、与图鉴/职位平级
缺点：比 A 多一个接口
C · 远期 完整洞察中心
B + 行业横向对比 + 趋势（需数据积累）+ 政策分析（外部数据源 + AI 解读）。

后端：+接口 +数据源 +AI 编排
工期：1-2 周
定位：二期迭代方向，本期不单独实施

四、推荐方案 B 页面结构

行业观察视图 (侧边导航 · 市场组) ├─ 顶栏: 搜索行业 + 排序切换 (岗位数/薪资/红旗率) + 样本说明 ├─ 行业卡片墙 (网格) │ 卡片: 行业名 | 在招 N 岗 | 薪资中位 + 市场溢价徽标 | 红旗率徽标 | 技能 Top3 ├─ 行业详情页 (视图内, 空间充足) │ ├─ 头部: 四指标 (岗位数/公司数/薪资中位/红旗率) │ ├─ 薪资结构: 行业中位 vs 市场 P25/P50/P75 + 经验-薪资折线 (行业口径) │ ├─ 技能热度: 行业技能 Top10 (需求数 + 溢价) │ ├─ 信号雷达: 加班重/外包/出差 + 红旗率 vs 全市场 │ ├─ 代表公司 Top8 → 点击开全局公司抽屉 │ ├─ 岗位列表 → 点击进现有职位详情 │ └─ [远期] 行业政策分析: 预留挂载位 └─ 联动: 观察台图表行加「查看行业」入口
实现要点：后端在 store/observatory.py 新增 observatory_industry_detail(conn, industry)（按行业过滤重算薪资分位/经验-薪资/技能 Top/红旗信号/代表公司，约 60 行纯 SQLite）；前端按组件岛模式新增 views/industry.html/js/css 三件套；侧边导航「行业观察」占位项启用。样本 <5 的行业详情页降级（只出概览卡，不出分位图）避免误导；「未知」行业默认排除、底部单列。
