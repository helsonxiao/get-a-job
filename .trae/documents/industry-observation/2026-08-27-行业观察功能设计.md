> 日期：2026-08-27 ｜ 对应 TODO#3：「支持行业观察和下钻查询功能，后续支持分析行业政策」

## 一、背景与目标

### 1.1 要解决的问题

求职决策的三个层次：**岗位层**（这个岗位值不值得投）→ **公司层**（这家公司值不值得去）→ **行业层**（这个行业值不值得待）。当前工具已有岗位打分与公司图鉴，行业层是缺失的一环——而行业选择往往比具体岗位更影响长期收益。

### 1.2 目标（本期）

1. **行业总览**：一眼看出哪些行业在招人、给钱多、风险低
2. **行业下钻**：点进一个行业，看它的薪资结构、技能需求、红旗信号、代表公司
3. **岗位打通**：行业 → 岗位列表 → 现有职位详情链路复用
4. **零成本起步**：尽量复用现有观察台聚合数据，不引入新依赖

### 1.3 非目标（本期）

- 不做行业趋势的时间序列（数据积累不足，抓取历史才有意义）
- 不做行业政策分析（需外部数据源 + AI 编排，列入路线图）
- 不改动后端数据模型

## 二、数据现状盘点（能支撑什么）

| 数据 | 来源接口 | 可用字段 | 说明 |
|---|---|---|---|
| 行业分布 | `/api/stats` | 行业名 + 岗位数 | 全量，含城市 |
| 行业薪资 | `/api/observatory/salary` | by_industry：中位数 + 样本数（Top10，样本≥2） | 已有 |
| 行业信号 | `/api/observatory/radar` | by_industry：加班重/外包/出差计数 + 红旗率（样本≥3） | 已有 |
| 技能×行业 | `/api/observatory/skills` | 每技能 top_industries | 已有 |
| 行业岗位下钻 | `/api/jobs?industry=X` | 完整岗位列表 + 打分 | 已有，可直接复用 |
| 代表公司 | `/api/companies?industry=X`（待确认列表接口支持） | 公司 + 分数/规模 | 图鉴接口 |
| 行业-薪资明细（分位/经验/学历） | 无 | — | **缺口**：需新聚合接口或客户端近似 |

**结论**：总览层数据 100% 现成；行业详情层约 80% 现成，缺"单行业薪资分位 + 经验/学历结构"，可以用现有 salary 接口的 by_exp/by_edu 按行业过滤近似（需要新接口，或在方案 A 中降级为"全市场口径 + 行业口径中位"）。

## 三、核心使用场景

1. **选行业**：换工作/投简历前，看哪些行业岗位多、薪资中位高、红旗率低（如"储能 vs 光伏 vs 半导体"）
2. **验证机会**：某个公司/岗位出现时，快速看它所在行业的薪资水位与竞争烈度（与详情页「市场参考」区块联动）
3. **下钻求职**：锁定行业后，直接看该行业的高分岗位列表，进入现有职位详情打分链路

## 四、方案设计（三选一）

### 方案 A：观察台内嵌「行业观察」Tab（最小改动 · 纯前端）

**信息架构**：市场观察增加第 5 个 Tab「行业观察」，与薪资/热力/雷达/技能平级。

**页面结构**：
```
行业观察 Tab
├─ 行业总览表 (全宽)
│  岗位数 | 公司数 | 薪资中位(万/年) | 相对市场溢价 | 红旗率 | 代表公司
│  排序可切: 岗位数 / 薪资 / 红旗率
└─ 点击行业行 → 行业详情抽屉 (复用 obs-drill 模式)
     ├─ 概览: 岗位数/公司数/薪资中位/红旗率 四卡
     ├─ 薪资对标: 行业中位 vs 全市场中位 (条状对比)
     ├─ 技能 Top5: 该行业需求技能 (来自 skills 接口聚合)
     ├─ 红旗信号: 加班重/外包/出差 (来自 radar 接口聚合)
     └─ 代表公司 Top5 + 该行业岗位列表 → 点击进现有详情
```

**实现要点**：新增 `views/observatory.js` 内一个 tab 分支 + 一个聚合函数（并行拉 salary/radar/skills 三个接口，客户端按行业名合并）；详情抽屉复用现有 obs-drill 模式（title/sub/jobs），公司查看直接复用全局公司抽屉。**零后端改动**。

| 维度 | 评估 |
|---|---|
| 改动范围 | 仅 observatory.html/js/css，约 1 个 Tab + 1 个聚合函数 |
| 后端 | 无 |
| 工期 | 0.5-1 天 |
| 优点 | 最快落地；与现有观察台语境一致；数据全复用 |
| 缺点 | 行业详情是"抽屉内嵌"，空间有限，后续加政策分析没地方放；行业作为"观察台的附属维度"而非一等公民 |

### 方案 B：独立「行业观察」视图 + 轻量聚合接口（推荐 · 中等改动）

**信息架构**：启用侧边导航「市场」组的「行业观察」占位项，成为独立视图；「市场」组变成 市场观察（市场总览）/ 行业观察（行业视角）并列。

**页面结构**：
```
行业观察视图
├─ 顶栏: 搜索行业 + 排序切换 (岗位数/薪资/红旗率) + 样本说明
├─ 行业卡片墙 (响应式网格)
│  卡片: 行业名 | 在招 N 岗 | 薪资中位(万/年) + 相对市场溢价徽标 | 红旗率徽标 | 技能 Top3 标签
│  点击卡片 → 行业详情页
├─ 行业详情页 (视图内, 非抽屉, 空间充足)
│  ├─ 头部: 行业名 + 岗位数/公司数/薪资中位/红旗率 四指标
│  ├─ 薪资结构: 行业中位 vs 市场 P25/P50/P75 (SVG 条) + 经验-薪资折线 (行业口径)
│  ├─ 技能热度: 该行业技能 Top10 (需求数 + 薪资溢价)
│  ├─ 信号雷达: 加班重/外包/出差 + 红旗率 vs 全市场
│  ├─ 代表公司: Top8 (公司分/均薪/在招, 点击开全局公司抽屉)
│  └─ 岗位列表: 该行业岗位 (可筛选/排序, 点击进现有职位详情)
│  └─ [远期] 行业政策分析区块: 预留挂载位
└─ 与市场观察联动: 观察台各图表行可"查看行业"跳转
```

**实现要点**：
1. 后端：`store/observatory.py` 新增 1 个函数 `observatory_industry_detail(conn, industry)` → 返回该行业的薪资分位（按行业过滤 salary_mid 重算 P25/P50/P75/均值）、经验-薪资、技能 Top、红旗信号、代表公司；路由 `/api/observatory/industry/{name}`。纯 SQLite 查询，无新依赖，约 60 行
2. 前端：新增视图岛三件套 `views/industry.html/js/css`（沿用组件岛模式）+ 侧边导航启用占位项
3. 政策分析挂载位：详情页底部预留区块（本期显示"规划中"占位，后续接入）

| 维度 | 评估 |
|---|---|
| 改动范围 | 后端 1 接口 + 前端 1 视图岛 + 导航启用 |
| 后端 | +1 聚合接口（约 60 行，无新依赖） |
| 工期 | 2-3 天 |
| 优点 | 行业成为一等公民；详情页空间充足；政策分析、行业对比等后续能力有天然挂载位；与图鉴/职位平级，符合"功能越来越多"的承载诉求 |
| 缺点 | 比 A 多一个接口；工期略长 |

### 方案 C：完整行业洞察中心（远期路线图 · 本期不实施）

B + 以下增量：
- **行业对比**：多选 2-4 个行业横向对比（薪资分位/红旗率/技能重叠度表格）
- **行业趋势**：按抓取时间序列（需数据积累，抓取 ≥3 轮后才有意义；可先做"最近 30 天 vs 更早"的粗粒度）
- **行业政策分析**：接入外部政策文本（政府网站/新闻搜索）+ AI 摘要与"对求职者影响"解读，落位在行业详情页预留区块；需要新增数据源接入与 AI 任务编排（与现有 AI 打分 runner 同架构）

**定位**：作为 A/B 落地后的二期迭代方向，不单独作为本期选择。

## 五、方案对比与推荐

| 维度 | A 观察台 Tab | B 独立视图（推荐） | C 洞察中心 |
|---|---|---|---|
| 后端改动 | 无 | +1 聚合接口 | +接口 +数据源 +AI 编排 |
| 前端改动 | 1 Tab + 聚合函数 | 1 视图岛 + 导航 | B + 对比/趋势/政策 |
| 工期 | 0.5-1 天 | 2-3 天 | 1-2 周 |
| 行业详情空间 | 抽屉内嵌（受限） | 完整页面 | 完整页面 |
| 政策分析挂载 | 无位置 | 预留区块 | 完整实现 |
| 与观察台关系 | 附属维度 | 平级视角 | 平级 + 联动 |
| 风险 | 低 | 低 | 中（依赖外部数据） |

**推荐：方案 B**。理由：行业观察是 TODO#3 的正式落位，不是观察台的临时维度——独立视图的完整空间才能承载"薪资结构+技能+信号+公司+岗位+政策"的递进深度；新增的 1 个聚合接口是纯 SQLite 查询，成本极低；同时 A 的总览表逻辑可直接复用在 B 的卡片墙中，B 实施时可先做 A 的总览部分再做详情页，风险可控。

若希望最快见到效果、且暂时不碰后端 → 选 A，后续再从 A 平滑升级到 B（抽屉改为页面即可）。

## 七、决策点

1. **方案选择**：A（最快纯前端）/ B（推荐，独立视图+轻接口）/ C 暂不选
2. **本期是否接受后端新增 1 个只读聚合接口**（B 方案前提；不改数据结构、不写数据）
3. **政策分析**：本期只预留挂载位（推荐），还是完全不预留等二期再说

## 八、风险与说明

- 行业样本量差异大（储能 8 岗 vs 计算机软件 35 岗）：详情页图表对样本 <5 的行业降级显示（只出概览卡，不出分位图），避免误导
- 行业名来自 BOSS 直聘口径（公司行业字段），存在"未知"（75 岗）：总览表默认排除"未知"行，单独在底部列出
- 新增接口与现有 `/api/observatory/*` 同域，SSE/轮询/缓存机制不受影响
