# 规则体系全面优化计划 (v3.1 → v4.0)

## 背景与调研结论

### 业界方法论要点

| 方法论 | 核心观点 | 对当前体系的启示 |
|--------|----------|------------------|
| **冰山模型** (McClelland 1973) | 显性层(知识/技能)占30%, 隐性层(能力/动机/价值观)占70%决定长期绩效 | 当前体系偏重显性匹配(技能/经验), 隐性层(文化适配/动机)覆盖不足 |
| **AI人岗匹配三层模型** | 岗位要求(能胜任) + 职业诉求(愿留下) + 文化适配(留得久) | 当前缺文化适配维度 |
| **选Offer第一性原理** | 选3年后最值钱的, 成长权重应最高(业界建议40%) | 当前默认成长30%, 偏低; 缺"3年价值"视角的评分项 |
| **总包折现率** | base现金确定性最高, RSU打6-8折, 期权按0算 | 当前F-04股权激励不分上市公司/创业公司, 等同对待 |

### 当前体系盲点

1. **学历/经验**: G-05只扣分不淘汰, 硬性不符时仍可能高分通过
2. **文化适配**: 完全缺失, profile有`tech_culture`字段但未在评分中使用
3. **通勤**: profile有`max_commute_minutes`和GPS坐标, 但W-05只判断城市是否匹配, 粒度太粗
4. **股权折现**: F-04不分上市公司股票vs创业公司期权
5. **技术前瞻性**: 缺少"3年后值不值钱"的视角, 不评估技术方向是否为热点
6. **公司稳定性**: 无财务健康度/团队流失率信号

## 详细改动

### 1. 新增硬规则 (scoring.py `run_hard_checks`)

#### H-09 学历硬性不符
- **判定**: 岗位要求学历 `rank` 高于用户 `profile.education` 对应 rank (rank越小要求越高: 1=博士 2=硕士 3=本科 4=大专)
- **逻辑**:
  - `edu.unlimited=True` 或 `edu.level` 为空 → 不命中
  - `profile.education` 为空 → confidence=0.4 (REVIEW, 让AI核实)
  - `edu.rank < profile_edu_rank` (岗位要求高于本人) → hit=True, confidence=1.0 (fatal)
  - `edu.rank >= profile_edu_rank` → 不命中
- **阈值来源**: `profile.education` (画像编辑)
- **detail**: "岗位要求学历高于本人最高学历。判定逻辑: 岗位edu.rank < 本人edu.rank即命中, 命中即淘汰(无置信度衰减, 学历要求是硬门槛)"

#### H-10 经验年限硬性不符
- **判定**: 岗位要求最低年限 `exp.min_years` 超过用户 `profile.total_years`
- **逻辑**:
  - `exp.unlimited=True` 或 `exp.min_years` 为空 → 不命中
  - `profile.total_years` 为空 → confidence=0.4 (REVIEW)
  - `exp.min_years > profile.total_years + 1` (超出1年以上) → hit=True, confidence=1.0 (fatal)
  - `exp.min_years > profile.total_years` 但 `<= total_years + 1` → hit=True, confidence=0.5 (REVIEW, 1年以内差距可放宽)
- **阈值来源**: `profile.total_years` (画像编辑)
- **detail**: "岗位要求最低年限超过本人总年限。判定逻辑: 超出1年以上直接淘汰, 1年以内标REVIEW交AI核实"

#### profile.py 需新增 helper
- `education_rank() -> int | None`: 把 `self.education` 字符串(如"本科""硕士")映射为 rank (3/2/1/4), 供 H-09 使用
  - 映射表: 博士→1, 硕士→2, 本科→3, 大专→4, 其他→None
  - 已有 `parse_profile_text` 中的学历解析, 这里只需补 rank 映射

### 2. 评分项新增与增强 (scoring.py)

#### 2.1 finance 维度: F-04 增强 + F-06 新增

**F-04 股票/期权激励** (增强判定, 满分不变 0.5):
- 当前: 福利含"股票/期权/股权"即满分
- 改为: 区分确定性
  - 上市公司(`company.stage` 含"上市") + 股票 → 满分 (RSU折现率高)
  - 未上市 + 期权 → 满分×0.3 (期权折现率低, 按0.1-0.3算)
  - 未上市 + 股票(RSU) → 满分×0.7
  - 无股权 → 0
- **detail 更新**: "股权激励的折现率: 上市RSU→满分, 未上市RSU→70%, 创业期权→30% (期权按彩票算)"

**F-06 薪资构成质量** (新增, 默认满分 0.5):
- **判定**: 评估薪资包的确定性
  - JD 明确月薪×月数 (如 25K×14薪) → base占比明确, 满分
  - 只给年薪范围无月数 → 满分×0.6 (可能含绩效/股权)
  - 面议 → 0
- **override_key**: `f06_max`
- **detail**: "薪资构成的确定性: 明确base月薪×月数→满分, 仅年薪范围→60%, 面议→0"

#### 2.2 growth 维度: G-07 新增

**G-07 技术前瞻性** (新增, 默认满分 1.0):
- **判定**: JD是否涉及当前技术热点 (3年价值视角)
- **信号来源**: `signals.infer_tech_forwardness(jd_text)` 返回命中热点列表
- **热点词表**: AI/大模型/LLM/AIGC/机器学习/深度学习, 云原生/K8s/Service Mesh, Web3/区块链, 低代码平台, 跨端/Flutter/RN, 大数据/数据中台
- **评分**: 命中≥1项 → 满分, 0项 → 0
- **override_key**: `g07_max`
- **detail**: "JD是否涉及AI/云原生/Web3等热点方向, 评估3年后的技术资产价值"

#### 2.3 resource 维度: R-05 新增 (文化适配)

**R-05 文化适配信号** (新增, 默认满分 2.0):
- **判定**: JD文化关键词 vs `profile.tech_culture` 的匹配度
- **信号来源**: `signals.infer_culture(jd_text)` 返回推断的文化标签列表
- **文化标签词典**:
  - 技术驱动型: "技术驱动/极客/开源/代码review/技术分享/工程文化"
  - 扁平管理型: "扁平管理/直接沟通/少层级/敏捷/Scrum"
  - 结果导向型: "结果导向/OKR/目标驱动/效率/产出"
  - 创新型: "创新/试错/探索/孵化/内部创业"
  - 传统型: "流程规范/KPI考核/层级/汇报/审批" (反向信号)
- **评分**:
  - `profile.tech_culture` 为空 → 0 (不加分, 也不触发AI)
  - 推断文化标签与 `profile.tech_culture` 命中≥1 → 满分
  - 推断为传统型且 `profile.tech_culture` 含"技术驱动/创新" → 0 (反向不匹配)
- **override_key**: `r05_max`
- **detail**: "从JD推断企业文化(技术驱动/扁平/结果导向/创新), 与画像偏好匹配"

#### 2.4 wlb 维度: W-05 增强 (通勤距离)

**W-05 通勤便利** (增强判定, 满分不变 1.0):
- 当前: 只判断 `job.city == profile.current_city`
- 改为: 同城时用 GPS 坐标计算直线距离, 估算通勤时长
  - `job.gps` 和 `profile.home_lng/home_lat` 都存在 → 算直线距离
  - 直线距离 → 估算通勤时长 (直线距离÷平均速度30km/h × 1.3蜿蜒系数 + 10min等车)
  - `profile.max_commute_minutes` 存在 → 对比:
    - ≤ max_commute → 满分
    - > max_commute 但 ≤ max_commute×1.5 → 满分×0.5
    - > max_commute×1.5 → 0
  - `profile.max_commute_minutes` 为空 → 距离≤15km满分, ≤30km半分, >30km零分
  - GPS缺失 → 回退到当前城市匹配逻辑
- **detail 更新**: "同城用GPS估算通勤时长, 对比画像max_commute_minutes; GPS缺失时回退到城市匹配"

## 假设与决策

1. **维度结构不变**: 保持 finance/growth/resource/wlb 四维度, 不合并不新增维度。resource 语义扩展为"平台与文化适配", 但代码层面 key 仍为 `resource`。
2. **默认权重不变**: 仍为 30/30/30/10, 通过预设方案引导用户调整, 不强制改默认值。
3. **GPS 通勤为估算**: 直线距离÷速度估算, 不调用地图 API (避免外部依赖)。精确度足够做相对比较。
4. **学历 rank 映射**: 复用 models.py 中已有的 `education.rank` 字段 (Job 侧), profile 侧新增 `education_rank()` helper 做同样映射。
5. **向后兼容**: 规则版本 4.0, 已有 `scoring_config.json` 中的 f01~f05/g01~g06/r01~r04/w01~w05 覆盖值继续生效; 新增项 f06/g07/r05 未配置时走默认值。
6. **重新打分**: 规则变更后用户需手动点"规则打分" (已有 `force=true` 机制), 不自动触发。

## 验证步骤

### 单元验证
1. H-09 学历: 构造 rank=2(硕士) 的岗位 + rank=3(本科) 的画像 → 应 fatal
