# 个人发展路径（能力规划 + 财务测算）方案

> **状态：待决策 · 2026-09-10 建档 · 未开工**
> 定位：**辅助判断，不替代判断。** 不做自动批量投递，不做收益承诺。
> 本方案不新起炉灶，是在既有 `gaj/strategy.py` 之上从「诊断」推进到「规划 + 算账」。

---

## 1. 动机

用户提出的产品方向：分析就业市场 → 结合自身已有能力 → 制定学习提升计划 → 计算财务投入与未来收益。

差异化判断：**市场数据 + 个人技能画像 + 学习投入的财务测算，这条链目前没人串起来。**

| 已有品类 | 缺什么 |
|---|---|
| 在线课程平台 | 只说学什么，不算账（存在利益冲突） |
| 职业社区 | 靠经验帖，无本地市场数据 |
| 薪资数据平台 | 只有数据，没有个人路径 |
| 自动投递工具 | 明确不做（见产品哲学） |

商业价值：城市报告是一次性消费（复购弱）；「我的路径 + 我的账」个性化、高感知、**可季度复购**（更新画像后看差距变化）。这是把客单价从 ¥9.9 往上提的合理路径。

### 2.2 ⚠️ 实测：画像解析层是坏的，且是静默坏

用真实 `data/profile.md` 跑 `parse_profile()`：

```
{'salary_k_min': None, 'salary_k_max': None, 'city': None, 'skills': ['是'], 'direction': None}
```

三处不匹配（正则 vs 画像实际字段）：

| 字段 | 正则期望 | profile.md 实际 | 结果 |
|---|---|---|---|
| 薪资 | `25-35K` 形式 | `当前年薪（万元）: 23` / `期望最低年薪（万元）: 30` | 解析为 `None` |
| 城市 | `期望城市：` | `可接受城市: 上海, 无锡, 苏州` | 解析为 `None` |
| 技能 | `(技能\|技术栈)[：:]` | `技能关键词列表: React, RxJS, …` | **误命中「接受更换技术栈: 是」→ 得到 `['是']`** |

**后果**：技能缺口一节不会报错，而是走到 `elif` 分支，输出「市场技能需求 Top5 + 提示补充技能」——**看起来正常，实际是错的**。这比崩溃危险。

> 结论：L1 的地基当前是空转的。**做任何新功能之前，先修解析层并加断言**（解析不到关键字段应显式告警，而非静默降级）。

## 3. 三层结构

| 层 | 做什么 | 数据是否够 | 依赖 | 建议优先级 |
|---|---|---|---|---|
| **L0 差距对照** | 已有能力 vs 市场需求的技能差集 | 够（需先修解析） | 修 `parse_profile` | **先修** |
| **L1 路径排序** | 学什么、按什么顺序 | 够 | L0 + 邻近度因子 | **P1 · 首个新功能** |
| **L2 财务算账** | 投入 / 回本周期 / 概率门槛 | **不够** | 技能溢价按职能分层 | P1，须等数据 |
| **L3 成长曲线** | 年限 × 薪资轨迹 | 不够 | 需跨期快照积累 | P2 远期 |

### L1 的关键设计：排序不能只按需求量

当前 `strategy.py` 的技能缺口按 `demand_count` 取 Top5，这会推荐 Java（112 岗）、Vue（75 岗）这类**最卷或早已掌握**的技能，对决策无意义。

排序应改为三因子：**需求量 × 溢价 × 邻近度**。
其中**邻近度**（该技能离你现有栈多远）是决定学习成本的主因子——学 Go 对会 Java 的人，与学 K8s 对只写前端的人，成本差数倍。

邻近度实现：先做人工维护的技能邻接表（30–50 个技能，分同生态 / 相邻生态 / 跨栈三档）；若 `jobs` 表保留 JD 原文，后期可用技能共现矩阵自动生成。

## 4. 核心风险：技能溢价 ≠ 学习收益

**这是本方案最大的技术陷阱。** `salary_premium` 是相关关系，不是因果关系。

苏州 291 岗 bundle 的实证（fingerprint `5aa9b13379fef7fe` / `8104`）：

| 技能 | 岗位数 | 均薪（万/年） | 溢价 |
|---|---|---|---|
| typescript | 33 | 21.6 | +20% |
| python | 66 | 21.0 | +16.7% |
| spring cloud | **18** | 21.0 | +16.7% |
| spring / spring boot | 39 | 16.2 | **−10%** |

两个反例：

1. **同生态差 26.7 个百分点**——`spring` 与 `spring cloud` 属同一技术栈，溢价差 26.7 个点不可能是真实价值差。`spring cloud` 仅 18 个岗位样本，均薪方差大到无意义。
2. **职能混淆**——算法/AI 职能薪资中位 23.4 万，后端开发 17.4 万，差 34%。TypeScript +20% 的溢价里，很大一部分是「这类岗位集中在高薪赛道」，而非技能本身值钱。

> **结论**：直接用 premium 算「学会能多赚多少」，等于把赛道溢价记到技能头上，系统性高估。一问即破。

**硬前提（L2 的前置条件）**：

1. 技能榜**按职能分层**输出（同一技能在后端岗 / 算法岗各自的溢价），schema 需加 `by_function`；
2. 每个技能给 **p25 / p50 / p75** 而非单一 `avg_salary`，让方差可见；
3. 样本量门槛：`demand_count` 低于阈值（建议 20）的技能标注「样本不足，溢价仅供参考」。

## 5. 财务测算的口径：反推回本门槛，不做收益预测

**不输出「学这个能多赚 X 万」，输出「要涨多少才回本，以及你需要多大把握」。**

三个输出量：

1. **投入** = 课程/资料费用 + 学习小时 × 当前时薪（**时间成本通常远大于金钱成本**）
2. **回本周期** = 投入 ÷ 预期年增薪
3. **概率门槛** = 反推：这笔投入要回本，需要多大的「学成并兑现」概率

示例（数字仅示意）：学费 3000 元 + 120 小时 × 115 元/时（按年薪 23 万 / 2000 工时估）＝ 投入约 1.68 万。若目标涨薪 3 万/年，账面回本 0.56 年，看着划算；但若「学完真能拿到这 3 万」的概率只有 40%，期望收益 1.2 万 < 投入 1.68 万，**实为亏损**。

工具最终给出的那句话应是：**「这笔投入要回本，你得有 56% 的把握在一年内兑现 3 万涨幅。你觉得有吗？」**

为什么这样设计：

- 把不可验证的预测，换成用户自己可判断的假设；
- 与产品哲学一致——「工具的价值是提升判断质量，不是替代判断」，与「不自动投递」是同一件事的两面；
- **天然抗抄袭**：无法一键 AI 生成，因为必须用户自己输入预算、时间和概率判断。

## 6. 数据 / schema 改动清单

| # | 改动 | 影响层 | 成本 |
|---|---|---|---|
| 1 | 修 `parse_profile`：对齐 profile.md 实际字段 + 解析不到时显式告警 | L0 | 低 |
| 2 | profile.md 新增「每周可投入学习小时」「可接受投入预算上限」 | L2 | **零成本，可立即加** |
| 3 | 技能邻接表（人工维护 30–50 技能 × 3 档） | L1 | 低 |
| 4 | bundle `skill_leaderboard` 加 `by_function` 分层 | L2 | 中（schema + 重算） |
| 5 | 技能薪资改出 p25/p50/p75 + 样本量标注 | L2 | 中 |
| 6 | 跨期快照积累（依赖「快照自动化 + 行情趋势」条目） | L3 | 高 |

> #1 与 #2 无依赖、成本极低，可与决策并行先做。#4/#5 未落地前，L2 不应开工。

## 7. 待决策（人拍板）

1. **推进顺序**：先 L0 修复 + L1 路径排序（数据现成、可快速验证付费意愿），还是直接冲 L2 财务算账（须先补分层数据）？——**建议前者**。
2. **财务口径**：确认采用「回本门槛」而非「收益预测」。这条决定产品是决策辅助还是算命。
3. **是否现在补分层数据**（#4/#5）：属 schema 改动 + 重算，是 P1 工程。

## 8. 风险与红线

| 风险 | 处置 |
|---|---|
| 一旦给出「学这个多赚 X 万」即构成承诺，用户会拿结果来验证 | 措辞必须是门槛与假设，禁止预测式表述 |
| 个人信息敏感性高 | 本地计算、不上传、不落库远端，与「不抓个人隐私数据」边界一致 |
| 推荐具体课程会有带货嫌疑，且数据支撑不了「哪门课好」 | **不推荐任何具体课程**，只算「你打算花的钱」 |
| 技能溢价被误读为因果 | 输出必须附样本量与口径说明，低样本显式标注 |

---

## 9. 建议推进顺序

```
① 修 parse_profile + 补两个画像字段      （无依赖，立即）
        ↓
② L1 路径排序（需求 × 溢价 × 邻近度）      （现有数据够，首个新功能）
        ↓
③ 技能溢价按职能分层 + 出分位数           （schema 改动）
        ↓
④ L2 财务算账（回本门槛）
        ↓
⑤ L3 成长曲线                            （需跨期快照，远期）
```

② 完成后即可作为付费版新增价值点验证市场反应；③ 未落地前不开工 ④。
